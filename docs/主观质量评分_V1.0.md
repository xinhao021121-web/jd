| V1.0 | 2026/09/21 | 首版：三个维度的 1–5 评分标准、评分流程、与机器评测的分工、边界声明；**评分已由本人完成** |

> 对应差距：[作品集差距诊断_V2.0.md](作品集差距诊断_V2.0.md) 的 **N5（评测体系缺「人评」一侧）**。
> **这份评分的定位：方法演示，不是外部证据。** 评分者是产品作者本人，样本 8 组、评分者 1 人——它证明的是「这套人评方法能跑起来」，不是「这个产品的主观质量达到了某个水平」。

## 一、为什么机器评测之外还要人评

现有评测全是**机器可判定**的规则：数字与技能能否溯源、套话黑名单、长度区间、锁定区块。它们能回答「有没有违规」，回答不了三件事：

1. **像不像真人写的**——规则判不了语气，黑名单只能拦住已知的套话；
2. **敢不敢直接发出去**——这是用户的真实决策点，只有人能给答案；
3. **有没有夸大**——规则只能查「简历里有没有这个数字」，查不出「语气上是不是把参与说成了主导」。

所以这三项交给人评，与机器评测是分工关系：**机器守住底线（合规、溯源、长度），人判断质量（像不像、敢不敢发）。**

## 二、三个维度与 1–5 的判据

评分对象：每组样本生成的 **3 条话术作为一个整体**（用户发送时是从 3 条里挑 1 条，不是逐条发）。

### A. 像不像真人写的

| 分 | 判据 |
|----|------|
| 1 | 明显机器腔，套话成串（「贵公司岗位非常感兴趣」式） |
| 2 | 能读，但句式模板化，读两行就出戏 |
| 3 | 基本像人写的，个别措辞生硬 |
| 4 | 像同行随口写的一段，读不出机器痕迹 |
| 5 | 完全像本人手写，带个人语气 |

### B. 敢不敢直接发送

| 分 | 判据 |
|----|------|
| 1 | 不敢发，会立刻改 |
| 2 | 要大改才敢发 |
| 3 | 改一两处就敢发 |
| 4 | 基本可直接发，顶多微调标点 |
| 5 | 一个字不改直接发 |

### C. 无夸大（越界风险越低分越高）

| 分 | 判据 |
|----|------|
| 1 | 明显夸大：写了简历里没有的经历或数字 |
| 2 | 有夸张表达，容易被追问 |
| 3 | 基本贴合简历，个别地方拔高 |
| 4 | 与简历一致，措辞克制 |
| 5 | 完全经得起追问，逐句都能在简历里找到依据 |

## 三、评分流程

1. 打开 `reports/主观评分_样本输出.md`（8 组样本 × 3 条话术，2026/09/21 由线上真实模型生成）；
2. 对每组样本，按上面三个维度各打一个 1–5 分；
3. 把 24 个分填进第四节的表；
4. 汇总时同时给出**每个维度的均分**与**三项总均分**，并指出得分最低的样本——低分样本比均分更有用，它指向下一次要改什么。

**注意**：评分时不要回看质量回归报告里的机器结论，否则会被人评之外的信息污染。

## 四、评分记录（已填）

**评分者实际给出的形式**（按本人说明记为「**每组 3 条候选话术中最好那一条的得分**」，不是三条整体、也不是按 A / B / C 分维度）：原始输入原样记下，不做二次加工：`3；1；2；3；2；2；2；2`。

> 这个口径与第二节写的「3 条作为一个整体」不同。**执行的这一版按本人实际做法登记**，不按原设计改数——把「最好一条」的分当成「三条整体」的分，会系统性高估质量。

| 样本 | 场景 | 最好一条的得分 |
|------|------|-------------|
| S1 | Java 后端 · 电商交易 | 3 |
| S2 | 前端 · 中后台系统 | **1** |
| S3 | 数据分析 · 指标体系 | 2 |
| S4 | 产品经理 · B 端工具 | 3 |
| S5 | 测试开发 · 质量保障 | 2 |
| S6 | 运维开发 · 容器化 | 2 |
| S7 | 算法工程 · 推荐方向 | 2 |
| S8 | 平面设计 · 品牌视觉 | 2 |

> 两点由此受限，**不编数据补齐**：① 没有 A / B / C 三个维度各自的分，所以**不给出分维度均分**；② 只记了每组最好那条的分，**没有记另外两条**，所以「同组里差的那两条差到什么程度」无从判断。第三节的判据仍然有效——它定义了这位评分者是在什么尺度上给出这些分的。

## 五、评分结果与结论

| 指标 | 数值 |
|------|------|
| 样本数 | 8 |
| 口径 | 每组取 **3 条候选里最好的那一条**（最有利于产品的取法） |
| 均分 | **2.13 / 5**（17 / 8） |
| 最高分 | 3（S1、S4） |
| 最低分 | **1（S2 · 前端）** |
| 分布 | 3 分 × 2、2 分 × 5、1 分 × 1；**没有任何一组的「最好一条」达到 4 分** |

按第三节的判据换算，2.13 分落在「能读，但句式模板化，读两行就出戏」「要大改才敢发」这一档。

**三条观察**：

1. **这个均分与产品的核心承诺是冲突的，而且取的是最有利的口径。** 本产品对外说的是「复制一条**敢直接发送**的话术」，评分口径又已经宽松到「每组只算 3 条里最好的那条」——即使这样，均分仍只有 2.13，**没有任何一组的「最好一条」达到「基本可以直接发」的 4 分**。如果按三条整体评，这个数只会更低。**这条冲突必须记下来，不能藏。**
2. **问题不是个别样本，是分布。** 8 组里 5 组是 2 分，分布在 Java、数据分析、测试、运维、算法、平面设计六个完全不同的方向上——说明措辞质量是**系统性问题**，不是某个场景没调好。
3. **人评这一侧确实补上了机器测不出来的东西。** 同一批样本在机器评测里是「95.8% 条级合规率、0 例编造」，看起来接近满分；人评给 2.13。**两者不矛盾**：机器守的底线守住了，而质量层此前没人测过——这正是 N5 存在的理由。

**由这份结果直接产生的待改进项**（不在本轮范围内，不在此处下结论）：

- 拿 S2 与得分较高的 S1、S4 做 bad case 归因，看差异出现在句式、信息密度还是第一句的落脚点上；
- 判断「像不像真人写的」能不能拆成可执行的提示词约束（例如句式必须变化、第一句直接给匹配点），改完再用同一套判据重测一次——**同一批评分者、同一批样本，重测才能看出改动是否有效**。

## 六、这份评分不能支撑什么

- **样本量**：8 组样本、1 名评分者，任何百分比都谈不上统计意义；
- **评分者偏见**：评分者就是产品作者，存在「希望分数好看」的自证倾向——这一条必须写进报告，不能省；
- **算不出一致率**：评分者一致率需要 ≥2 名评分者，单人评分没有这个数，因此**不能**声称「评分稳定」；
- **不是外部证据**：它替代不了外部盲测；[公开讨论材料_V1.0.md](公开讨论材料_V1.0.md) 里的「不得写成访谈」同理，这里**不得写成「用户调研」或「用户满意度」**。

**引用时必须带上的那句局限**（照抄即可）：

> 这是作者本人对 8 组样本的主观评分，属于方法演示：评分者即产品作者、样本 8 组、无第二名评分者因而不存在一致率，不能代表用户评价。
