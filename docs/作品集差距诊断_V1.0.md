## 一、结论

三句话：

1. **强项在「实现可信度」**：六版 PRD、六版技术方案、覆盖单测与文档一致性与端到端的自动化测试、限流压测、覆盖率门槛、回滚演练、线上冒烟。这部分已高于多数同类作品集，继续加码的边际收益很低。
2. **缺口在「用户证据」**：全文没有一条来自本人的访谈、问卷或可用性测试；核心价值指标（会话级复制率、建议采纳率）口径已落地，但数据恒为空。
3. **所以差距不是「做得少」，是配比失衡**：绝大部分文档与测试在回答「我做对了吗」，没有一条在回答「该不该做」——而后者才是 AI 产品经理岗被考核的主轴。

## 三、补齐计划

三个阶段各自独立可交付，做完一阶段就能拿去投递一次；不要并行开工，否则又会回到「什么都做了一半」。

### 阶段一：可对外投递的最小集（G1 / G2 / G3 / G4）

目标：把「没有一条外部证据」和「文档无主」这两个致命项清零。预估 3–4 个工作日。

1. 跑完 [盲测](../reports/blind-test/发给测试者的话.md) 的邀请与回收，产出 `reports/盲测报告_<时间>.md`；
2. 按 [指标回收决策_V1.0.md](指标回收决策_V1.0.md) 选定一条路径并落地，回收至少 1 份真实使用记录；
3. 用 [用户访谈提纲_V1.1.md](用户访谈提纲_V1.1.md) 做 ≥3 人访谈，把痛点证据替换掉主文档第一节的推演标注；
4. 填完主文档第八节三张表。

**完成标志**：G1–G4 的四条验收标准全部满足，且主文档第七节第 1 条不再出现「尚无访谈或问卷」这类自认缺口。

### 阶段二：补齐 PM 的核心证据（G5 / G6 / G7 / G8 / G9 / G10）

目标：让作品集能回答「质量怎么量化」「为什么这么选型」「单位经济性如何」「合规边界在哪」「别人怎么看到它」「这么做的价值观是什么」。预估 4–6 个工作日。

**完成标志**：G5–G10 验收标准全部满足，主文档新增或更新三节（评测方法、成本、定位与边界）。

### 阶段三：方法论升级与收口（G11 / G12）

目标：回答最尖锐的两个追问——「去掉 AI 能不能做」与「用户拿到 offer 之后呢」。预估 2–3 个工作日。

**完成标志**：G11 的对比结论与 G12 的判断各写进主文档一节；两节的结论都要能被仓库里的命令或实验复现。

## 五、本文档不做什么

- 不改产品代码与 PRD 口径，不动既有测试断言（唯一例外是新增本文件的文档一致性测试后，同步三处写死的测试条数）；
- 不写死会过期的数字，测试条数以 `pnpm test:counts` 的输出为准；
- 不代替主文档第八节的本人认领，也不把本文件的结论当成已确认事实。
