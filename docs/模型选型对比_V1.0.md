# 模型选型对比

版本号：V1.0 ｜ 2026/09/21

| 版本 | 时间       | 备注                              |
|------|-----------|-----------------------------------|
| V1.0 | 2026/09/21 | 首版：对应差距诊断 G6 与 G7 的实测     |

> 对应差距：[作品集差距诊断_V1.0.md](作品集差距诊断_V1.0.md) 的 **G6（模型选型无对比）** 与 **G7（成本只有护栏，没有单位经济性）**。
> 复现：`pnpm model:compare -- --models=<模型名,模型名> --samples=8`；原始报告写在 `reports/模型选型对比_<时间>.md`（该目录默认不入库，需要留档时 `git add -f`）。

## 一、怎么测的

| 项 | 做法 |
|----|------|
| 样本 | `tests/samples/quality-samples.json` 的 8 组简历 + JD，与质量回归同一批 |
| 任务 | 每样本跑话术与改写建议两项，共 16 次调用/模型 |
| 提示词 | 与线上完全一致（`packages/llm` 的 `buildMessages`，脚本不另写一份） |
| 质量判定 | 与线上同一个本地自检函数（`packages/core`），判「合规性」，不是「好不好」 |
| 候选 | 端点 `/v1/models` 列出的 `deepseek-flash`、`deepseek-v4-pro`，加产品当前使用的 `deepseek-chat` |
| 用量 | 客户端开启 `stream_options.include_usage`，由端点回传 `usage` 后累加 |

> 一个需要记录的细节：`deepseek-chat` 不在 `/v1/models` 的返回列表里，但实测可正常调用（16 次全部成功），也是 [质量回归_V0.2.md](质量回归_V0.2.md) 一直使用的模型。
> `deepseek-v4-pro` 单次生成约 50 秒，跑满 8 组需要十几分钟，因此它只跑了 2 组（4 次调用）；这个样本量足以支撑它在延迟维度的结论，但不足以支撑质量维度的结论。

## 二、结果

### 8 组样本的全量对比（`deepseek-chat` 与 `deepseek-flash`）

| 模型 | 运行次数 | 违规合计 | 平均首字 | 平均完整 | 平均 input | 平均 output |
|------|---------|---------|---------|---------|-----------|------------|
| **deepseek-chat** | 16 | 5 | **457.7 ms** | **1687 ms** | 721.6 | **298** |
| deepseek-flash | 16 | 4 | 8481.9 ms | 9454.3 ms | 746.6 | 2355.3 |

### 一次完整生成（话术 + 改写建议）

| 模型 | input tokens | output tokens | 合计耗时 |
|------|-------------|--------------|---------|
| **deepseek-chat** | 1443.3 | **596** | **3374 ms** |
| deepseek-flash | 1493.3 | 4710.5 | 18908.6 ms |
| deepseek-v4-pro（2 组） | 1670.5 | 12455 | 101203.5 ms |

### 倍率（以 `deepseek-chat` 为基准）

| 模型 | 完整耗时 | output token | 是否满足 PRD 的「完整 ≤30 秒」 |
|------|---------|-------------|---------------------------|
| deepseek-chat | 1× | 1× | 满足 |
| deepseek-flash | 5.6× | 7.9× | 满足（9.5 秒），但首字 8.5 秒已越过「首字 ≤5 秒」 |
| deepseek-v4-pro | 30× | 20.9× | **不满足**（50 秒） |

### 违规分布（同一套本地自检）

| 模型 | 违规位置 |
|------|---------|
| deepseek-chat | S6 话术 1 处；S7 话术 2 处、建议 2 处 |
| deepseek-flash | S1 话术 1 处；S2 话术 1 处；S3 建议 1 处；S5 话术 1 处 |
| deepseek-v4-pro | 2 组样本 0 处 |

## 三、结论

1. **质量维度上没有分出高下。** 三个模型都有违规，`chat` 5 处、`flash` 4 处、`pro` 在 2 组样本上 0 处——样本量下这点差异不足以支撑「换模型能提升质量」。真正的质量短板在提示词与自检规则，不在模型。（`pro` 的 0 处也不能当成优势，它只跑了 2 组。）
2. **延迟维度上差距是数量级的。** `chat` 1.69 秒、`flash` 9.45 秒、`pro` 50.6 秒。`pro` 已经越过 PRD 承诺的「完整结果 ≤30 秒」，`flash` 的首字 8.5 秒也越过「首字 ≤5 秒」——**两个候选都被性能门槛直接排除**，这与「质量差不多」叠加起来，选型结论是明确的。
3. **token 成本上差距同样是数量级的。** 一次完整生成的输出 token：`chat` 596、`flash` 4710、`pro` 12455。`flash` 与 `pro` 的输出量异常高（约 8 倍与 21 倍），推测是把推理过程计入了 `completion_tokens`——这是**推测，未验证**，但无论成因如何，计费口径下的差距是实测的。
4. **当前选型经受住了这次对比。** 产品用的 `deepseek-chat` 在同端点的三个候选中，延迟与 token 用量都最低，质量同量级。这就是「为什么用这个模型」的答案。

> 结论的边界：只覆盖一个端点（`https://api.deepseek.com/v1`）上的三个模型，未做跨供应商对比；`pro` 只跑了 2 组；质量判定只用本地自检，主观质量由外部盲测覆盖。

## 四、单位经济性（G7）

实测下来，一次完整生成（话术 + 改写建议）用 `deepseek-chat` 消耗 **1443 输入 + 596 输出 token**；单次调用（只跑话术或只跑建议）平均 **722 输入 + 298 输出 token**。

折算方式是两项相加：

```
单次成本 = 输入 token / 1,000,000 × 输入单价 + 输出 token / 1,000,000 × 输出单价
```

**官方公开价（2026/09 查自 `api-docs.deepseek.com/quick_start/pricing`，人民币 / 百万 tokens）**：

| 模型 | 输入（缓存未命中）空闲 / 高峰 | 输出 空闲 / 高峰 |
|------|---------------------------|----------------|
| `deepseek-flash` | 1 元 / 2 元 | 4 元 / 8 元 |
| `deepseek-v4-pro` | 4.5 元 / 9.0 元 | 13.5 元 / 27.0 元 |

空闲时段价格是高峰的一半；高峰为北京时间周一至周五（不含法定节假日）9:00–12:00 与 14:00–18:00，其余时段（含周末与节假日全天）都按空闲计。

按 `deepseek-flash` **空闲时段、缓存未命中**（即最便宜的一档）折算：

| 口径 | 成本 |
|------|------|
| 单次调用（722 输入 + 298 输出） | ≈ 0.0019 元 |
| 一次完整生成（1443 输入 + 596 输出） | ≈ 0.0038 元 |
| 1 万次完整生成 | ≈ 38 元 |
| 当前部署硬顶（300 次调用/日 × 30 天） | **≈ 17 元/月** |

几个可以直接用的结论：

- **当前部署的成本是有硬顶的**：`DAILY_CALL_CAP=300` 之下即使额度每天用满，单月模型成本也在十几元量级；成本在这个体量上不是主要约束，**选型的主要约束是延迟**；
- 「1 万次完整生成」约等于 500 名用户各投 20 个岗位，折算下来约 38 元；
- 单次成本对输出 token 极其敏感：`flash` 与 `pro` 的差距几乎全部来自输出侧，输入侧三者接近（1443 / 1493 / 1670）。要换模型，先看输出 token；
- 缓存命中价只有未命中的 1/50（0.02 元对 1 元），但本产品的输入每次都包含不同简历与 JD，**几乎没有缓存复用空间**，所以按未命中价估算更接近实际。

**两个必须说清的边界**：

1. **产品实际调用的模型名 `deepseek-chat` 没有出现在官方定价页上。** 该页只列 `deepseek-flash` 与 `deepseek-v4-pro`，并写明：「模型名请使用 `deepseek-flash`。旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用，但对应模型已下线，请求将由 DeepSeek-V4.1-Flash 模型提供服务，并按 Flash 价格计费。」`deepseek-chat` 是否同样属于旧名兼容、按哪一档计费，**必须以账单为准**——上面的数字是按 Flash 公开价折算的估算，不是账单核对值；
2. **只算了模型调用。** Cloudflare Worker 与 Durable Object 在当前用量下不产生费用，未计入。

## 五、这次对比没有回答什么

1. **主观质量**：自检只能判「有没有编造、有没有套话、长度是否合规」，判不了「像不像真人写的」——那要靠 [外部盲测](作品集差距诊断_V1.0.md)（G3）。
2. **跨供应商**：只有这一个端点。要回答「为什么不用别家的模型」，需要另一个可调用的端点。
3. **模型版本迭代后的回归**：本次是单次快照。端点换版本后，延迟与 token 都可能变，需要重跑。
4. **单价的账单核对**：token 是实测的，单价是使用者要填的输入项。

## 六、怎么复现

```bash
# 需要可用的端点与密钥（读取仓库根目录的 .env）
pnpm model:compare -- --models=deepseek-chat,deepseek-flash --samples=8

# 带单价折算（单价由使用者提供）
pnpm model:compare -- --models=deepseek-chat --samples=8 --price-in=0.15 --price-out=0.6

# 快速验证脚本本身
pnpm model:compare -- --models=deepseek-chat --samples=1
```

汇总逻辑（均值、一次完整生成口径、成本折算）有单测覆盖，见 `tests/model-compare.test.ts`；真实调用只在本地手动跑，不进 CI。
