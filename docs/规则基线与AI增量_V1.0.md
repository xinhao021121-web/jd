# 纯规则基线：AI 的增量到底是什么

版本号：V1.0 ｜ 2026/09/21

| 版本 | 时间       | 备注                                |
|------|-----------|-------------------------------------|
| V1.0 | 2026/09/21 | 首版：对应差距诊断 G11 的实测           |

> 对应差距：[作品集差距诊断_V1.0.md](作品集差距诊断_V1.0.md) 的 **G11（AI 的必要性未被论证）**。
> 要回答的追问是：**去掉 AI，用关键词匹配 + 模板是不是也能做？**
> 复现：`pnpm baseline:compare`；只跑规则版零成本验证用 `pnpm baseline:compare -- --skip-model`。

## 一、怎么测的

| 项 | 做法 |
|----|------|
| 样本 | 与质量回归、模型选型同一批 8 组简历 + JD |
| 规则版口径 | 关键词匹配 + 模板：复用产品自己的 `analyzeMatch` 取命中技能，从简历里抽年限、技能清单与含数字的量化行填槽，改写建议则是在相关行尾追加「JD 关注且简历确实拥有」的术语 |
| 判定 | 两侧都用产品自己的本地自检（`packages/core` 的同一组函数），规则完全一致 |
| 模型版 | `deepseek-chat`，同一批样本、同一套提示词 |

**基线是刻意做认真的**：它只填简历原文里存在的技能与数字，不编造；它的输出要先过产品自己的自检。这样它不会靠「编造」输掉对比——如果它输了，输在哪才是要测量的东西。

## 二、结果

| 指标 | 规则版 | 模型版 | 含义 |
|------|-------|-------|------|
| 合规违规数 | **22** | **6** | 数字溯源 / 套话 / 长度 / 锁定区块，同一套判定 |
| 跨样本话术相似度 | 0.115 | 0.034 | 换一个岗位，产出有多像（3-gram Jaccard） |
| 重复句比例 | **0.514** | **0.03** | 有多少句子是原样复用的 |
| 改写理由相似度 | **1** | **0.018** | 1 表示所有理由都是同一句 |
| 每样本耗时 | 约 0 ms | 3502 ms | 规则版无网络与推理开销 |
| 每样本 token | 0 | 1443 输入 + 610 输出 | 规则版成本为零 |

### 两侧各自输在哪

规则版 22 处违规的构成很集中：

- **话术长度不足 12 处**（63–99 字，低于 100 字下限）——模板骨架是固定的，简历里可填的量化内容不够时，它凑不到长度；
- **改写长度超限 10 处**——在行尾追加「（涉及 X、Y）」会把原文撑爆 40% 的红线。

模型版 6 处违规：长度越界 3 处；另 3 处集中在 S8（平面设计）——它给出了「建议与原文一致」的空建议，被自检判为越界。

还有一个细节值得记下来：**S8 的规则版产出了 0 条改写建议**。原因是它的候选术语来自「JD 要求 ∩ 简历拥有」，而 S8 的 JD 与简历几乎没有关键词交集，规则版就无话可说了；模型版在同样条件下仍然产出了 4 条建议（其中 3 条不合格，但它在尝试）。

## 三、结论

1. **AI 的增量不是「能不能生成文字」——模板也能生成。** 增量在于**既能达标又不重复**：规则版 22 处违规对模型版 6 处。规则版不是靠编造输的（它只填原文内容），它是靠「凑不出长度」和「加术语撑爆长度」输的。
2. **增量更明显地体现在「换一个岗位，产出会变」上。** 重复句比例 0.514 对 0.03，改写理由相似度 1 对 0.018：规则版给出的理由永远是同一句「补上岗位关注的术语」。
3. **这一点直接对应产品的立项理由。** 这个产品要解决的问题是「复制同一段会被招聘者一眼看出模板」；而用模板方案去解决模板问题，它的输出里有 **51.4% 的句子是原样复用的**。逻辑上不可能成立——这不是效果好坏，是方向不成立。
4. **规则版唯一的优势是成本与延迟**：0 token、约 0 ms，对模型版的 1443 + 610 token、3.5 秒。**如果这个产品的目标是「批量产出能直接发的话术」，那规则版够用；但那个目标和产品定位是冲突的。** 成本在这里不是主要约束（见模型选型对比：当前部署的成本硬顶是个位数量级）。

## 四、这次对比没有回答什么

1. **基线可以做得更好，结论的强度要按这个打折。** 一个更认真的规则实现可以准备多套骨架、按 JD 类型挑选，相似度会下降。但那本质上是把「生成」退化成「检索 + 拼接」：骨架数量是人工成本，覆盖不了长尾岗位，也仍然处理不了「简历与 JD 没有关键词交集」这类情况（S8 就是例子）。
2. **主观质量仍未测量。**「规则版读起来更像模板」目前只有重复句比例这个代理指标，真正的判断要靠外部盲测（G3/G5）。
3. **单批样本、单一模型。** 8 组样本足以看出量级差异，不足以给出精确比例；换模型后两侧的相对关系可能变化。
4. **没有测「用户能不能察觉」。** 重复句比例 0.514 是我定义的量化代理，招聘者实际察觉的阈值没有数据。

## 五、怎么复现

```bash
# 两版都跑（16 次真实调用）
pnpm baseline:compare

# 零成本：只跑规则版，验证脚本本身
pnpm baseline:compare -- --skip-model

# 换样本量或模型
pnpm baseline:compare -- --samples=4 --models=deepseek-chat
```

汇总逻辑（槽位抽取、模板生成、相似度与重复句比例）有单测覆盖，见 `tests/baseline.test.ts`；其中一条断言专门钉住「规则版话术必须能通过产品自己的自检」，防止基线被改成稻草人。
