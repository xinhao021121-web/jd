## 一、结论与范围

本次只做四件事，目的是把「产品规则」从提示词里挪回确定性代码，并删掉模型在做却没人用的输出：

1. **本地自检**：话术与改写建议的「无编造、去套话、不堆表情」由 `packages/core` 的纯函数在服务端逐条执行，命中只标注不丢弃；
2. **提示词不再让模型自检**：删掉「输出前逐条自检字数/数字/技能」这类模型做不到的自审要求；
3. **模型不再输出本地已知字段**：`index` 与 `style` 由本地按回传顺序赋值，模型写错或不写都不影响展示；
4. **建议任务不再重复投喂简历全文**：只给可改写区块原文与锁定区块标题。

PRD 3.2 的验收口径（三要素齐全、100~160 字、无套话、事实可溯源）没有变化，变化的是**执行者**：模型负责写，本地负责判定。

## 二、本地自检的落点与偏差处理

| 项 | 约定 |
|----|------|
| 实现位置 | `packages/core/src/quality.ts`：`checkGreetingText`（单条话术）、`checkSuggestionText`（单条建议）、`checkGreetings` / `checkSuggestions`（整批，含条数与长度，供质量回归复用） |
| 调用位置 | `apps/api` 的 `POST /api/llm`：模型每回传一条 item 就立刻自检，随事件一起下发；未命中时不带 `issues` 字段 |
| 判定范围 | 数字溯源、技能溯源、套话黑名单、表情符号；**不含长度与条数**——长度由前端 `offSpecGreetingIndexes` 提示，条数由既有「只返回 N 条」提示覆盖，避免两处重复报警 |
| 偏差处理 | **命中只标注不丢弃**：丢弃会让「3 条话术」的契约失效，也会让用户失去本可自行修正的内容；改写建议仍保留原有硬约束——锚点落在锁定区块的建议继续直接丢弃，不进前端 |
| 单一实现 | 线上兜底与离线质量回归（`pnpm quality:samples`）调用同一份函数，判定规则不允许有两套 |
| 日志 | 只把命中条数写进 `errorType`（`FLAGGED_n` / `DROPPED_n`），不记录话术与建议正文 |

**为什么不让模型自审。** 让模型「输出前自检」在实现上等于再让它猜一次自己的输出：既不能给出可验证的结论，又要为这段自审多付输出 token；而数字是否出现在简历里、是否用了黑名单词，本地是几行确定性的字符串比较。自检结果一旦由本地产生，就能被单测钉住、也能在 UI 上逐条提示。

## 三、提示词收缩

| 改动 | 之前 | 之后 |
|------|------|------|
| 自检要求 | system 第 8 条要求「输出前逐条自检：字数、数字、技能」 | 删除；只保留「事实溯源」「长度区间」这类写作要求 |
| 输出字段 | 每行必须带 `index` 与 `style` | 示例只留 `{"type":"item","kind":"greeting","text":"..."}`，`index` / `style` 由本地赋值 |
| 建议任务上下文 | 简历全文 + 可改写区块摘要（同一段内容发两遍） | 只发可改写区块原文 + 锁定区块标题；锁定区块正文不再进入请求体 |

**量化（`tests/fixtures.ts` 样例：简历 423 字、JD 279 字）**

| 指标 | 之前 | 之后 | 变化 |
|------|------|------|------|
| 话术 system 提示词 | 797 字 | 740 字 | −7% |
| 话术单次输入合计 | 1738 字 | 1681 字 | −3% |
| 建议单次输入合计 | 2030 字 | 1640 字 | −19% |
| 建议任务里可改写区块原文的出现次数 | 2 次 | 1 次 | 去重 |

简历越长，建议任务的降幅越大：去掉的正是与可改写区块等量（样例中占全文 86%）的重复内容。

**只有自检要求被删，写作要求保留。** 第一版收缩时顺手删掉了「技能匹配型 / 经历相关型 120~150 字、简短直接型 110~140 字」这段目标字数，随后真实模型复跑立刻在同一批样本上复现「简短直接型」长度越界（92 / 96 字），与 [质量回归_V0.2.md](质量回归_V0.2.md) 首轮记录的问题同类。该段已恢复——它是写作要求（指导模型写多长），不是自检（让模型判断自己写对没有），见第六节复跑记录。

## 四、协议变更

| 项 | 约定 |
|----|------|
| `index` / `style` | `GreetingItemEventSchema` 与 `SuggestionItemEventSchema` 里改为可选；服务端回传前按顺序重写，`index` 即回传序号，`style` 取 `GREETING_STYLES[序号]` |
| `issues` | 两个 item 事件新增可选字段 `issues: string[]`，由服务端本地自检产生，前端只读展示 |
| 防注入 | 模型若自己在输出里带 `issues`，服务端一律用本地计算结果覆盖，模型无法伪造「已通过自检」 |
| 兼容 | 旧客户端不带 `issues` 时按无问题处理；旧模型不输出 `index` / `style` 时服务端补齐，不再因缺字段丢行 |

## 五、成本与风险

| # | 风险 | 缓解 |
|---|------|------|
| 1 | 词典级自检存在漏检（简历里的技能未收录进 `SKILL_RULES`、数字表述形态特殊） | 只做「命中即提示」的软兜底，不宣称零漏检；离线质量回归仍是更全的验收口径 |
| 2 | 命中过多会让用户疲劳 | 逐条提示而非整页警告，且不阻断复制与采纳 |
| 3 | 建议任务不再看到锁定区块正文 | 锁定区块本就不可改写；`isEditableAnchor` 仍在服务端二次拦截；区块清单缺失时以「无可改写区块」提示用户补小标题 |
| 4 | 成本不降反升（自检本身不花钱，但多了一次函数调用与事件字段） | 自检为纯字符串比较，单次开销可忽略；收益是一次生成的输入 token 与一次失败重试的概率同时下降 |
| 5 | 提示词删减误伤质量 | 收缩范围限定在「模型自审」与「本地已知字段」；写作要求（长度目标、事实约束、语气）保留，并由真实模型复跑确认残留量与 V0.2 同量级（见质量回归第六节） |

## 六、测试策略

| 层次 | 覆盖内容 |

| 纯逻辑（Vitest） | `checkGreetingText` / `checkSuggestionText` / `checkGreetings` / `checkSuggestions` 的判定边界（数字溯源含 K8s、Vue3、年份、年限；套话、表情、越界、改写引入新事实）；`greetingStyleFor` 的序号映射与越界回退 |

## 七、已知边界

- 自检是**规则式**的：技能以 `SKILL_RULES` 词典为准，词典外的技能名不会被判为「不可溯源」，也不会被拦；
- 不引入第二个模型做审核：审核模型既增加成本，又会把「有没有编造」这个可判定的问题重新变成不可判定的问题；
- 命中只提示，是否发送仍由用户决定；产品侧由此得到的硬保证只有一条：**改写建议永远改不到锁定区块**。
