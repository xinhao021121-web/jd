## 三、需要回填的字段

一行一个岗位。字段越少越填得完，因此只留 8 列：

| 字段 | 取值 | 去哪找 |
|------|------|-------|
| 日期 | YYYY/MM/DD（只到日） | BOSS 直聘「沟通过」列表；不确定时按聊天记录里最早一条消息的日期 |
| 公司 | 公司名 | 同上 |
| 岗位 | 岗位名 | 同上 |
| 渠道 | 直聘 / 其他平台 / 内推 / 其他 | 自己记得的；记不清就填「其他」 |
| 打招呼方式 | **复制同一段** / **按岗位手写** / **AI 辅助** | 回想当时怎么发的；拿不准时，凡是「几乎没改就发出去」的一律算复制同一段 |
| 是否改简历 | 是 / 否 | 简历文件有版本记录的按文件时间还原；没有的按记忆，拿不准填「不确定」并计入排除项 |
| 对方是否回复 | 是 / 否 | 聊天记录里**对方发过任意一条消息**才算回复；「已读」不算；系统自动回复不算 |
| 是否有效回复 | 是 / 否 | 回复里**问了具体问题或约面试**才算有效；纯拒绝、纯模板话术记「否」 |

**回填路径（按可靠性排序）**：

1. **BOSS 直聘的「沟通过」列表**——投递量最大的一段，主要靠这里；
2. **简历文件的时间戳**——用「原文件名_定制.docx」与简历版本的修改时间，反推「什么时候改了简历」，这比回忆准；
3. **邮箱与微信里的面试邀约、拒信**——用来核对「有效回复」这一列，也用来看有没有漏记的岗位；
4. **记忆兜底**——只在不影响结论方向时使用，拿不准的标「不确定」。

**预计耗时**：100 行左右，30–45 分钟。**不必一次填完**，先填最近 1 个月（约 30 行）就已经能出结论。

## 四、口径定义（先定死，否则数字没有意义）

| 口径 | 定义 | 为什么这么定 |
|------|------|------------|
| 一次投递 | 主动发起一次打招呼 | 被动收到邀约不算，因为本记录要回答的是「主动投递的回复分布」 |
| 有回复 | 对方发过任意一条消息（含拒绝） | 只要对方开口，就说明话术或简历过了第一道筛 |
| 有效回复 | 回复里问了具体问题或约面试 | 「有回复」里混着大量礼貌性拒绝，两类要分开 |
| 排除项 | 猎头与中介、同一公司同一岗位的重复投递、测试性投递 | 它们会污染分母 |
| 合并口径 | 同一公司投了多个岗位，**按岗位分别计**，不合并 | 每个岗位的 JD 不同，话术也不同 |

## 六、汇总要算什么

回填完之后，至少给出这四个数（**分母都要写出来**，不能只给百分比）：

| 指标 | 算法 | 汇报格式 |
|------|------|---------|
| 主动投递总数 | 有效行数（去掉排除项） | N 个 |
| 有回复率 | 有回复行数 / 总数 | M / N = XX% |
| 有效回复率 | 有效回复行数 / 总数 | K / N = XX% |
| 打招呼方式分布 | 三种方式各占多少 | 复制同一段 X% / 按岗位手写 Y% / AI 辅助 Z% |

另外给出两个交叉观察（**描述现象，不下因果结论**）：

- 「按岗位手写 / AI 辅助」的回复率与「复制同一段」相比是什么关系；
- 「改了简历」的岗位回复率与「没改」相比是什么关系。

## 七、这份记录能支撑什么、不能支撑什么

**能支撑**（可以写进作品集与面试回答）：

- 第一人称的真实投递量级与回复分布：「我在 2026 年 X 月到 Y 月主动投递 N 个岗位，其中 M 个有回复」；
- 本人打招呼方式与改简历投入的分布，用来解释产品为什么把「按 JD 生成话术」和「按 JD 改简历」作为两个动作。

**不能支撑**（写出来比藏着安全）：

- **不能推广到其他求职者**：这是 N=1 的记录，没有对照组，无法区分「行业普遍情况」与「我个人的情况」；
- **不能当因果证据**：回复率差异可能来自岗位匹配度、公司规模、投递时间，而不是话术本身；
- **不能替代用户调研**：它回答「我怎么做」，不回答「别人需要什么」；
- **不必美化**：如果数字很难看，如实写。求职本来就是这样，难看的是市场不是记录。

**引用时必须带上的那句局限**（照抄即可）：

> 这是作者本人 2026 年 X–Y 月的投递记录（N 个岗位），属于自身场景的纵向观察，样本为 1 人、无对照组，不能代表其他求职者。
